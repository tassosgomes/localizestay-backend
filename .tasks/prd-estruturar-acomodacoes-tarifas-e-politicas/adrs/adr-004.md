# ADR-004: Usar salvamento explícito e separar server, URL e form state

## Status

Accepted

## Data

2026-07-22

## Contexto

A F02 permite rascunhos progressivos, mas todas as alterações relevantes incrementam a revisão e podem invalidar uma validação vigente. Autosave ou optimistic update aumentariam o risco de conflitos silenciosos entre operadores.

A feature também possui filtros compartilháveis, formulários extensos, diálogos e estado remoto que não devem ser duplicados em uma store global.

## Decisão

Usar:

- TanStack Query para server state;
- URL para filtros, ordenação e paginação;
- React Hook Form para formulários;
- `useState` para diálogos e expansão;
- salvamento explícito por seção;
- mutations sem retry automático e sem optimistic update;
- refetch após mutation para obter a revisão atual;
- tratamento explícito de `REVISION_MISMATCH`;
- chave idempotente local e estável para cada tentativa de envio.

Nenhuma store global de domínio será criada.

## Alternativas Consideradas

### Autosave com debounce

- **Prós:** reduz cliques.
- **Contras:** aumenta mutations, invalida validações durante edição e dificulta conflitos.
- **Por que rejeitada:** não combina com revisão comercial concorrente.

### Store global de rascunho

- **Prós:** centraliza edição extensa.
- **Contras:** duplica server state e cria sincronização adicional.
- **Por que rejeitada:** URL, Query e React Hook Form cobrem os estados necessários.

## Consequências

### Positivas

- Limites claros entre estado remoto e visual.
- Conflitos ficam visíveis.
- O backend permanece soberano sobre revisão e completude.
- Refresh e links preservam filtros.

### Negativas

- O operador precisa confirmar cada seção.
- Algumas mutations exigem refetch adicional.

### Riscos

- Perda de alterações locais ao navegar; mitigar com aviso de formulário sujo.
- Revisão mudar durante preenchimento; mitigar preservando valores e solicitando reconciliação.

## Notas de Implementação

- Não descartar valores do formulário após `REVISION_MISMATCH`.
- Bloquear navegação acidental com formulário sujo.
- Não repetir automaticamente mutations.
- Submissão manual reutiliza a chave apenas enquanto representar a mesma tentativa.
